# KLIKO

Многостраничный сайт KLIKO на Next.js 16 и Payload CMS 3.88.

## Локальный запуск

1. Скопируйте `.env.example` в `.env.local` и задайте `DATABASE_URL` и длинный случайный `PAYLOAD_SECRET`.
2. Запустите PostgreSQL. Подготовленный `compose.yaml` поднимает локальную базу на порту `5433`:

   ```bash
   docker compose up -d postgres
   ```

3. Установите зависимости и подготовьте базу:

   ```bash
   npm install
   npm run payload migrate
   npm run seed
   ```

4. Запустите сайт:

   ```bash
   npm run dev
   ```

Публичная часть доступна на `http://localhost:3000`, защищённая панель — на `http://localhost:3000/admin`. При первом открытии Payload предложит создать первого администратора; после этого вход возможен только по его учётным данным.

До открытия production-сайта создайте первого администратора. Для дополнительной защиты внутренней панели рекомендуется ограничить `/admin` через Cloudflare Access. Для публичного endpoint лайков перед заметным трафиком настройте Cloudflare Rate Limiting или Turnstile.

## Статьи

- публикации, черновики и история версий хранятся в PostgreSQL;
- редактор Lexical поддерживает заголовки, списки, ссылки, цитаты, Markdown-сочетания, изображения и таблицы;
- дата публикации и число лайков редактируются вручную;
- публичные изменения лайков проходят через отдельный same-origin endpoint и не открывают общий доступ на изменение статьи;
- локальные загрузки попадают в `public/media` и исключены из Git;
- если заданы все пять переменных `R2_*` из `.env.example`, медиатека автоматически использует Cloudflare R2 через официальный S3-совместимый адаптер Payload. В репозитории секреты R2 не хранятся.

После изменения коллекций выполните `npm run generate:types`, `npm run generate:importmap` и создайте новую миграцию через `npm run payload migrate:create имя-изменения`.
